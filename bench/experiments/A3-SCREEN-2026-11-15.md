# A3 embedding candidates: preliminary screening

Frozen before screening results, 15 November 2026. This is an extension of
`LLAMACPP-MODELS.md`, not a change to the shipped default.

Compare the candidates individually in the existing M2 hybrid on the dev splits
of SciFact and Alloprof, against the recorded shipped pair. Use the existing lab
configuration, 512-token limit, and the model-specific query instructions. Screen
for an improvement of at least 0.01 nDCG@10 on either corpus. Results are tuning
evidence; SciFact contamination and the need for a separate held-out evaluation
remain. Record hardware, runtime, actual configuration, conversion, input hashes,
errors, time and memory. Do not compare timing under concurrent load as an idle
speed measurement. Query latency and ingestion speed need a separate idle run.

These are third-party Q8_0 GGUF conversions, not official author releases. Record
their exact revisions and hashes; verify configurations and model outputs before
interpreting quality. They do not establish parity with the original models.

The original repositories' tokenizer post-processors were inspected: Octen and
Harrier append `<|endoftext|>`; F2LLM appends `<|im_end|>`. An initial run was
interrupted before producing a score after the server was found to append the
token automatically. `a3_tokenizer_probe.py` verified that the converted GGUFs
produce the same token IDs as the original tokenizers on three short fixtures;
embedding usage also confirmed two tokens for `Hello`. The corrected v2 wrapper
does not append a token, and uses new model names to avoid the previous cache.
This fixture check is not a complete parity test or score reproduction. GPU
quality screening runs concurrently with a CPU indexing job; the elapsed
durations therefore are not idle speed measurements.
