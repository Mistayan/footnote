# Footnote overview, 19 November 2026

Where Footnote stands against its vision, product by product: competitors, measured performance, what could move to
Rust, how it is presented, and the cheapest path to a public 0.9 alpha. Every number links to the file it comes from.
Anything not measured is marked as such.

## 1. Vision and today

**Vision** (Johan, 14 November): one engine-agnostic harness for professional agentic work, in place of the many
single-purpose tools. Under the Footnote umbrella: Library (document corpora), Memory (what agents learn), Code (code
graph), plus Flow (the working method) and Alias (anonymisation). Two editions
([EDITIONS.md](../roadmap/EDITIONS.md)): **Footnote One**, free and Apache-2.0, for one person or a small team, and
**Footnote Enterprise**, paid, for anything that needs a company directory.

| Product | Vision | Today | Gap |
|---|---|---|---|
| Library | Cited, checkable answers over local documents and crawled docs, French and English | Shipped. Rust binary, MCP read-only, BM25 + two local embedding models, citations with hash and freshness | Docs crawling loses to Grounded Docs on Sphinx sites; PDF and OCR still go through optional Python helpers |
| Memory | Remembers how the user works, safely, across every agent | Shipped and used daily: hook recall, save flow, scopes, tags, review queue | Extraction quality is not measured; memory origin (#207) not built |
| Code | Code graph linked to Library docs and Memory fixes | Base layer shipped (scopes and imports resolution, compiler grades from SCIP) | Cross-product links (symbol ↔ docs ↔ past fixes) are designed, not built |
| Flow | Harness that saves money per accepted delivery against AI alone or AI + skills | Prototype and benchmark ladder running; integration bridge is Python | No result yet shows a saving; see section 3 |
| Alias | Anonymisation before text leaves the company | Built, copied to Enterprise | Waits for an Enterprise build |
| Launcher | One window to install models, see usage and projects | Tauri app, Windows only | #123 (Linux, macOS), #125 (installer) |
| Enterprise | SSO, rights, federation, audit export | Design only ([FEDERATION-DESIGN.md](../FEDERATION-DESIGN.md)) | Nothing built, by decision |

In short, the engine and the three core products work and have receipts. What is missing is proof of the harness
promise (Flow) and everything a company buyer needs (Enterprise).

## 2. Competitors, product by product

Only tools we have read or run. "Measured" means run on our machine with a stored result.

### Library

| Tool | What it is | Against Footnote |
|---|---|---|
| Grounded Docs (`arabold/docs-mcp-server`, MIT) | Docs crawler + SQLite FTS5 + sqlite-vec | **Measured: Footnote worse**, −0.203 nDCG@5 on the sealed final. Equal on Hono, lost on Flask, partly because Cloudflare blocked our crawl ([BACKLOG.md](../roadmap/BACKLOG.md)) |
| Context7 | Hosted docs lookup | Removed from Johan's agents on 15 November; not measured. GSD's researcher agents still list it (with Ref, Exa, Firecrawl) as a docs source, so it joins the next sealed final (#277) |
| SQLite FTS5 tools (most local memory tools) | Lexical index | **Measured: Tantivy is 110 to 140 times faster** at 100k to 1M documents ([README](../../README.md)) |

On public retrieval sets Footnote beats published BM25 (SciFact 0.747 vs 0.665, NFCorpus 0.368 vs 0.325). We have not
run other memory tools on those sets, and the README says so.

### Memory

| Tool | Approach | Against Footnote |
|---|---|---|
| ICM | Local, LLM extraction at session end | **Measured on LongMemEval-S retrieval: Footnote 0.908 all@5 vs ICM 0.820** ([AGENT-MEMORY-DESIGN.md](../AGENT-MEMORY-DESIGN.md)) |
| Hindsight | Observations and opinions with confidence | Published: LoCoMo 92.0 %, PersonaMem 86.6 %. Not run by us |
| mem0 | LLM extraction on every add | Installed in `bench/.venv-mem0`; prompts read |
| Zep / Graphiti, Letta, LangMem, claude-mem | Temporal facts, sleep-time agents, side agent | Docs read only |

The weak spot for everyone, us included, is that no benchmark measures whether extraction kept the right things.
PersonaMem comes closest to the promise that it remembers how the user works, and we have not run it.

### Code

| Tool | Precision / recall vs compiler, Rust, without `tests/` |
|---|---|
| **Footnote base layer** | **0.98** / 0.50 |
| CodeGraph 1.6.3 (MIT) | 0.88 / **0.55** |
| codebase-memory-mcp 0.12.1 | 0.61 / 0.41 |

Source: [CODE-GRAPH-DESIGN.md](../CODE-GRAPH-DESIGN.md). Serena (GPL-3.0, live language servers) and GitNexus (PolyForm
Noncommercial) were not run. CodeGraph is the real competitor: slightly higher recall, about six times as many wrong
links. Footnote's planned edge is the cross-product link that no code-graph tool has.

### Flow

Its competitors are not products but alternatives: the agent alone, the agent with curated skills (GSD, marketingskills
and similar), and token savers (TokenEconomizer, RTK, Ponytail). The comparison that counts is cost and time per
accepted delivery (#244, #222). See section 3.

### Alias

Uses the OpenAI Privacy Filter plus our own rules, tested on held-out data. No head-to-head against other anonymisers
(for example Presidio) has been run.

## 4. Candidates for a Rust rewrite

The product is already Rust (about 17,400 lines in `src/` and `crates/`). Python remains in three places:

| Python code | Ship? | Recommendation |
|---|---|---|
| `flow/integration/footnote.py`, `flow/evaluation/*` | The integration bridge would ship with Flow | **Rewrite the bridge in Rust** when Flow becomes a product (FOOTNOTE-FLOW-DESIGN names this as unfinished). Keep the evaluation scripts in Python. |
| PDF text-layer and OCR helpers | Optional, installed by the user | **Rewrite next if E7 needs it.** Each Python dependency is an install step and a supply-chain surface. Decide after the OCR bench (#136). |
| `bench/`, `tools/` (experiments, receipts) | No | **Keep in Python.** They are lab code; a rewrite would only cost time. |

The Launcher's front end is JavaScript inside Tauri, as is normal, so it stays.

## 5. Presentation status

- **README:** complete and honest. Proof tables with receipts, limits stated, no claims against unnamed competitors.
- **PRODUCT.md / DESIGN.md:** exist (reviewed 12 November). PRODUCT.md still describes only the memory/corpus tool, not
  the umbrella or the two editions. It needs updating before launch.
- **Product page:** `design/site/index.html` (dark v2, approved by Johan on 14 November) and branch `draft/landing-page`.
  It has not been through the full QLoop review and has no hosting.
- **Per-product presentation:** not written. When it is, it must explain why **global preferences saved by agents wait
  for the user's review**. They are recalled into every prompt in every project and some grant permissions, so a single
  prompt injection could otherwise become a standing rule. #207 goes further: each memory records where it came from,
  and MCP writes default to project scope. The reasoning is in [AGENT-MEMORY-DESIGN.md](../AGENT-MEMORY-DESIGN.md),
  decision 5.

## 7. Website, SEO and SEA

- **Website:** one static page is enough for the alpha. Host it free on GitHub Pages or Cloudflare Pages. The only
  cost is a domain (about €10 to €15 a year). It must pass every Ship gate of the website-launch checklist (Johan's
  Definition of Done for an MVP). It needs no analytics, in line with the no-telemetry promise; if traffic numbers are
  needed, use the host's server-side counts.
- **SEO:** the audience is developers searching for problems ("local MCP memory", "agent memory citations", "French RAG
  local"). What ranks for them is a public GitHub repository with a clear README, a page per product with real
  benchmark tables, and listings in MCP directories (the official MCP registry, awesome-mcp lists). Write the
  comparison pages only for what we have measured: Footnote vs FTS5, Code vs CodeGraph, Memory vs ICM. open-seo, already
  reviewed, can check the pages.
- **SEA (paid ads): no, not for the alpha.** Developers rarely click ads, and there is nothing to convert to before
  Enterprise exists. Spend that money on the domain and a code-signing certificate later instead.

## 8. Minimal-spend plan to the 0.9 alpha

Decisions already made: Windows installer unsigned for now (#125), Linux/macOS launcher deferred (#123), real CI before
0.9 (#205).

1. **Make the public repository** (a fresh copy without Alias or company designs, as EDITIONS.md requires). This also
   fixes CI for free: **GitHub Actions minutes are free on public repositories**, so #205 needs no paid credits.
2. **CI (#205):** build, test and clippy on Windows and Linux runners in the public repository, required before merge.
3. **Release:** the existing `dist-workspace.toml` / `ci/release` branch, with the unsigned Windows installer and a
   SmartScreen note in the README.
4. **Update PRODUCT.md** for the umbrella and editions; finish the QLoop review of the product page; publish it on
   Pages with a domain.
5. **Proof for the launch:** finish the ladder run and publish its chart, run PersonaMem for Memory, and fix or
   disclose the Grounded Docs loss for Library.
6. **List** the MCP server in the official registry and the main awesome lists.

**Cash cost: the domain only** (≈ €15/year). Optional later: a code-signing certificate (≈ €100 to €300/year), and only
if SmartScreen warnings turn out to hurt installs.
