## Material usability edges, not missing fundamentals

1. **Deletion retains old chunks intentionally enough to remain gettable.** Tombstoning removes FTS rows but not chunks; `get` joins without an indexed-status predicate. Previously returned IDs for deleted paths can therefore return old text with `status/freshness=deleted`, while search excludes them (`src/app.rs:330-340,403-422,445-446,511-513`). Updated-source chunks, conversely, are deleted and old get IDs fail. An agent adapter must distinguish these outcomes; do not describe every old ID as uniformly unavailable.
2. **Stale is a label, not an exclusion.** Search can spend its bounded result budget on stale/missing sources or stale record evidence. This is transparent but leaves freshness policy to every caller (`src/app.rs:407-419,436-454`; `src/records.rs:146-152`). Repeated copies of identical evidence can also be rehashed repeatedly; no cache bug is established, but hashing is not free (`docs/ARCHITECTURE.md:30`).
3. **Semantic coverage can silently become partial from an agent's perspective.** Signatures prevent incorrect reuse after indexed changes, but no automatic dirty-item embedding queue exists. Returned `eligible_embeddings` is the semantic list length after top60 truncation, not a total coverage certificate; `eligible_items` counts eligible live items (`src/semantic.rs:265-283,330-331`). Useful health output should distinguish total valid vectors, pending items and stale/orphan vectors. Current stats reports only table counts (`src/app.rs:518-526`).
4. **Ingestion/write contention matters before OCR tuning.** The corpus scan holds an immediate transaction across traversal/extraction (`src/app.rs:215-343`); binary helpers may take 120 seconds per file (`src/extract.rs:51-65`). Embedding rebuild holds its own write transaction across inference (`src/semantic.rs:172-206`). Writers have a five-second busy timeout (`src/app.rs:95`). This is a serialization risk, not a measured contention failure in this audit.
5. **Extractor reuse is not a full environment fingerprint.** Reuse checks source bytes/helper/chunker, not the currently installed dependency environment (`src/app.rs:260-266`; `docs/ARCHITECTURE.md:26`). Changing packages alone can leave successful old extraction reused. Keep this explicit; it is distinct from stale source-byte detection.
6. **Retrieval is not an answer/action policy.** Lexical records reserve slots before text (`src/app.rs:436-454`); hybrid is bounded exact JSON-vector scan + RRF, not ANN (`src/semantic.rs:253-295`). It explicitly emits `answerability=not_estimated`; no automatic proposal validation or action authorization follows from scores (`src/semantic.rs:330-331`; `docs/OPERATIONS.md:9,31`).

Existing test sources cover stale/move/delete/dedup/read-only behavior (`tests/safety.rs:19-56`) and vector invalidation/rebuild/helper mismatch (`tests/hybrid_adversarial.rs:42-97`). These are inspected contracts, **not tests rerun by this audit**.

## Smallest next vertical slice — proposed, not implemented

**One opt-in local resident reader over one explicitly approved small technical root, preserving SQLite authority and the current citation/write contracts.** Do not simultaneously rewrite OCR, adopt a new model, add generic memory CRUD or globally activate an agent.

1. Give the existing CLI a narrow explicit resident-helper mode with one pinned tokenizer/ONNX session, bounded request IDs/queue/timeouts and owned start/stop/restart. Keep existing lexical CLI fallback. Expose search/get/stats through one local agent adapter (bounded JSON stdio is enough; full MCP is not prerequisite). First measure repeated actual agent calls, including model load separately, rather than translating harness timings into product claims.
2. Keep SQLite authoritative for source revisions/chunks/records; start with its existing vector path to isolate resident integration. **If Qdrant is chosen for this slice**, use a new explicitly owned collection as a derived index only. Add an idempotent revision/signature-bound pending-upsert/tombstone ledger in the same SQLite commit as index changes, replay it, and hydrate/recheck every candidate against SQLite before serving it. Otherwise stop at the resident SQLite slice: benchmark success alone cannot justify silently dual-writing.
3. Prove one continuous scratch-fixture journey: index → repeated resident search → get matching hash/revision → edit before rescan (stale, not actionable) → rescan (old vector/ID not current; changed-item coverage explicit) → refresh vectors → delete/rescan (no search hit; old get explicitly deleted or refused) → restart (same valid results, no stale cache). Retain existing proposal dedup/conflict and validation-revision behavior; no auto-promotion from retrieval. Use only authorized fixtures, not private notes.

**Acceptance:** actual warm end-to-end search/get timings and resident load count; bounded/clean owned shutdown and restart; explicit pending semantic coverage; no old revision returned as current after edit/delete/restart; original provenance and record/history preserved. Add a second root only with a document root/path filter applied consistently before both ranking branches. No cross-encoder or OCR speed gate is needed to establish this first usable personal-agent loop.

### Product contract versus experimental Qdrant

The authoritative-originals/structured-record contract is deliberate and useful for personal agents: files own original content; SQLite owns structured findings and history; source/chunk/FTS/vector tables are derived. A future Qdrant collection is likewise **derived** and must be safely rebuildable without deleting authoritative records/history. A Qdrant score/payload cannot be the sole authority for citation revision, current source bytes, scope or validation state.

Source inspection reconfirmed the entire Rust action/dispatch surface (`src/app.rs:27-81,456-516`), citation freshness (`403-422`), scan/update/delete (`189-345`), structured transitions (`src/records.rs:53-217`) and embedding signatures (`src/semantic.rs:112-208,237-267`). All five Rust modules contain **zero Qdrant references**. The scoped codebase-memory coverage query found an index dated `2026-10-17T08:48:45Z` and a known excluded `tools` subtree; graph metadata is not current/exhaustive proof. Direct source reads ground these findings; no index refresh was requested.

`tools/server_benchmark.py` supplies a real isolated `Server`, `ResidentEncoder` and benchmark `Pipeline`, not a CLI backend. Its pipeline hydrates a separate `documents` schema with hardcoded revision 1 (`267-274`); `qdrant_quality.py` uses frozen public excerpts/vectors and separate experiment collections. Reranking exists in ablation experiments, not current Rust search. The earlier harmonized comparison/quality limitations remain in [QDRANT-QUALITY.md](../QDRANT-QUALITY.md); its measurements were **not rerun here**. No Qdrant server was started/contacted, and no existing `borg_vault` collection/model compatibility was inferred.

**Operational gaps, ordered for this personal use case:**

1. No agent-callable Qdrant-backed search/get path over the actual source/chunk/record schema; no revision-bound Qdrant upsert/delete reconciliation or recovery of interrupted derived writes.
2. No resident product encoder ownership/readiness/restart/shutdown; no product reranker. Resident benchmark timing cannot stand in for repeated real agent calls.
3. Explicit scan is available, not a watcher. Source edits before scan only label stale results; after scan vectors can be partial until manual rebuild. Stats table counts do not certify complete semantic coverage (`eligible_embeddings` is also top60-truncated in general).
4. No generic structured record edit/supersede/delete commands. Do not suggest a nonexistent command because the schema reserves `superseded` or conflict text mentions it. Documents can be edited/deleted externally and rescanned; that is a different operation.
5. Search/get remain evidence retrieval, not an applicability/answerability decision: stale evidence must not be silently actionable, unknown applicability is not compatible, and the 90% presented-information gate remains unverified. Personal use removes irrelevant enterprise scope, not citation correctness.
